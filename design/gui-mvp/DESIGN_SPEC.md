# organize GUI · MVP 界面设计规格 v1

> 来源需求：Notion《📦 organize GUI · MVP 产品功能与交付规格》（2026-10-04 版）。
> 读者：负责实现界面的 Agent（技术栈 Tauri 2 + Vue 3 + TypeScript + Naive UI + Pinia + vue-i18n）。

## 0. 先读这里

**结论**：界面围绕一条“方案 → 文件夹 → 扫描 → 预览 → 整理 → 结果”的任务流设计。历史、撤销和隔离区放在一级导航，并在侧栏常驻“保护状态”卡片。

**交付物**

| 文件 | 用途 |
| --- | --- |
| `DESIGN_SPEC.md` | 本文件。实现时以本文件为准。 |
| `prototype.html` | 可点击的高保真原型。浏览器直接打开。顶部深色条是评审用导航，不属于产品界面。 |
| `screens/*.png` | 32 张静态设计稿（2 倍分辨率），覆盖全部页面和关键状态。 |
| `export-screens.sh` | 从原型重新导出 `screens/`。 |

**需要人判断的点**

1. 默认主题定为深色。规格要求“跟随系统”，深色只是首次启动的设计基准。见第 12 节。
2. 预览页把“冲突”统一叫作“重名”。这是文案决定，影响全部界面和错误提示。
3. 撤销预览里“整理后被修改过”的文件默认不勾选，但允许用户手动勾选。规格只写了“默认跳过并提示”，没写能否手动选。
4. 隔离区“恢复到其他位置”需要 `quarantine.restore` 接收目标文件夹参数。接口文档未写明。
5. 首次引导根据所选文件夹推荐方案（下载 → 方案 A，图片 → 方案 B）。推荐规则是设计假设。

**怎么验证**

1. 运行 `cd design/gui-mvp && python3 -m http.server 8765`。
2. 打开 `http://localhost:8765/prototype.html`，用顶部评审导航切换页面和状态。
3. 实现完成后，按第 11 节的清单逐项对照。

## 1. 设计方向

**一句话**：像一台精密仪器的控制台。它先显示完整的“航线”，用户确认后才执行。

四条原则：

1. **计划可见**。每个文件的“原位置 → 新位置”都能看到。科技感来自精确的数字和路径，不来自装饰。
2. **颜色只表达操作类型**。蓝色表示移动，琥珀色表示隔离，紫色表示撤销和恢复，红色只用于失败和离开应用控制的动作。
3. **一个主按钮，固定位置**。任务流每一页的主按钮都在底部操作栏右侧。按钮文字写明结果和数量，例如“整理 1,150 个文件”。
4. **安全感常驻**。侧栏底部常驻“你的文件受到保护”卡片，任务流顶部常驻安全提示。

唯一的动效重点是扫描页的“文件矩阵扫描线”。其他动效只响应用户操作。

### 2.2 字体

- 界面字体：`Geist`，中文回退 `PingFang SC` / `Microsoft YaHei UI`。安装包内置 Geist，不依赖网络。
- 路径字体：`Geist Mono`。**只用于文件路径**，不用于其他标签。
- 所有数字开启 `font-variant-numeric: tabular-nums`，避免进度数字跳动。

| 级别 | 字号 / 字重 | 用途 |
| --- | --- | --- |
| Display | 44 / 600 | 扫描页计数 |
| Stat-L | 28–36 / 600 | 预览总数、执行百分比 |
| H1 | 22 / 600 | 页面标题 |
| H2 | 15–16 / 600 | 卡片标题、弹窗标题 |
| Body | 13 / 400 | 正文 |
| Small | 12 / 400 | 说明、表格辅助信息 |
| Path | 12 / 400 Mono | 路径 |

### 2.3 尺寸、圆角、动效

- 圆角分三级：控件 6px，面板 10px，窗口 14px。不同层级不得用同一圆角。
- 间距基数 4px。页面左右内边距 28px，面板内边距 16px。
- 控件高度：小 26px，默认 32px，主按钮 38px。
- 动效时长：反馈 120ms，展开 200ms。开启“减少动态效果”时关闭全部动画。

## 3. 应用框架

### 3.1 窗口

- 默认尺寸 1280 × 820，最小尺寸 1040 × 680。
- 单实例：第二次启动时聚焦已有窗口，不弹提示。

### 3.2 布局

```text
┌────────────────────────────────────────────────────────────────────┐
│ 标题栏：应用名                                   ● 整理引擎已就绪   │
├──────────────┬─────────────────────────────────────────────────────┤
│ 侧栏 212px   │ [任务流步骤条]（只在任务流页面显示）                 │
│              ├─────────────────────────────────────────────────────┤
│ 首页         │ 页面标题 + 一句话说明                    [页面工具]  │
│ 整理历史     │                                                     │
│ 隔离区   12  │ 内容区（可滚动）                                     │
│ 设置         │                                                     │
│ 关于         │                                                     │
│              │                                                     │
│ ┌──────────┐ │                                                     │
│ │保护状态卡│ ├─────────────────────────────────────────────────────┤
│ └──────────┘ │ 底部操作栏：[次要/返回]      摘要文字      [主按钮] │
└──────────────┴─────────────────────────────────────────────────────┘
```

- **侧栏**：一级导航按规格固定为首页、整理历史、隔离区、设置、关于。隔离区右侧显示文件数；有超过保留天数的文件时，数字用 `quar` 色。
- **保护状态卡**：显示“可以撤销的整理 N 次”“隔离区里的文件 N 个”“永久删除：从不”。前两行可点击，分别进入历史和隔离区。
- **标题栏状态**：显示整理引擎状态。就绪为绿点；引擎崩溃时变红点，文字为“整理引擎已停止”。
- **任务流步骤条**：六步，依次为选择方案、设置文件夹、扫描、预览、整理、结果。右侧显示安全提示：整理前写“确认前不会改动任何文件”，整理开始后写“每个文件的去向都会记录，可以撤销”。
- **底部操作栏**：只在任务流页面、撤销预览页和隔离区（有选中项时）出现。左侧放返回或次要动作，中间右对齐放摘要，最右侧放唯一主按钮。

### 3.3 任务流导航规则

1. 扫描、预览、执行、结果不进一级导航。
2. 用户在任务流中点击侧栏离开时，侧栏“首页”下方出现虚线卡片“正在进行的任务”。点击它回到离开时的页面。
3. **执行中锁定侧栏**。侧栏导航变为 40% 透明且不可点击。这样用户不会在整理中途进入隔离区等页面。
4. 结果页属于任务流终点。离开结果页后，“正在进行的任务”卡片消失。

## 4. 统一词汇表

实现时所有界面文案必须使用左列用词。右列内部概念不出现在界面上。

| 界面用词 | 含义 | 内部概念 |
| --- | --- | --- |
| 方案 | 一套整理设置 | Profile、preset |
| 扫描 | 只读取文件信息，生成计划 | `plan.create` |
| 整理 | 按计划真正移动文件 | `run.execute` |
| 预览 / 整理计划 | 扫描结果列表 | Plan、PlanItem |
| 移动 | 文件换位置 | operation = move |
| 隔离 / 进入隔离区 | 文件移入应用管理的隔离目录 | operation = quarantine |
| 重名 | 目标位置已有同名文件，将自动改名 | TARGET_CONFLICT |
| 跳过 | 应用决定不处理（临时文件、被占用等） | status = skipped |
| 排除 | 用户在预览中取消勾选 | selected = false |
| 撤销 | 针对一次整理的整体动作 | `history.undo` |
| 恢复 | 把单个文件放回原位置 | undo 中的单项、`quarantine.restore` |
| 内容完全相同 | 重复文件判定结果 | 部分哈希、完整哈希 |
| 比对部分内容 / 比对完整内容 | 重复文件扫描阶段 | partial hash / full hash |
| 整理引擎 | 后台 Python 进程 | engine |
| 移入系统回收站 | 文件离开隔离区，交给操作系统 | `quarantine.moveToTrash` |

禁止出现：删除、永久删除（“从不”除外）、YAML、Jinja、哈希、规则语法、Profile、Plan。

## 5. 危险动作分级

| 级别 | 动作 | 颜色 | 确认方式 |
| --- | --- | --- | --- |
| L0 只读 | 扫描、查看、搜索、筛选、排除文件 | 主色或默认 | 无确认 |
| L1 可撤销 | 开始整理、隔离重复文件 | 主色 | 弹窗列出数量和后果，主按钮“开始整理” |
| L1 可撤销 | 撤销、恢复 | `undo` 紫色 | 先进入撤销预览页，再点主按钮 |
| L1 停止 | 停止整理 | `fail` 描边 | 弹窗说明“当前文件完成后停止”，默认按钮是“继续整理” |
| L2 离开应用控制 | 移入系统回收站 | `fail` 实心 | 弹窗写明“organize 不能再恢复它们”，按钮写数量“移入回收站（3 个）” |

规则：

1. 风险说明写在用户点击之前，放在按钮所在页面或确认弹窗内。
2. 确认弹窗的取消按钮在左，确认按钮在右。按 `Esc` 等于取消。
3. L2 弹窗的确认按钮不获得默认焦点。焦点默认在“取消”。

## 6. 页面规格

每页格式：目的、布局、内容、状态、交互、接口。截图编号对应 `screens/`。

### 6.1 首次启动引导（截图 01–03）

**目的**：30 秒内让用户理解“先预览、再整理、随时撤销”，并开始第一次扫描。

**布局**：全窗口覆盖，不显示侧栏。顶部三段进度条，内容居中，宽 760px。

1. **欢迎页**：标题“整理文件，不用担心弄乱”。三张卡片按顺序展示“先预览 → 再整理 → 随时撤销”。主按钮“开始”。
2. **选择文件夹**：四个磁贴：下载、桌面、图片、选择其他文件夹。前三个可多选，默认选中“下载”。最后一个打开系统文件夹选择器。
3. **选择方案**：四个方案卡片的紧凑版。根据第 2 步推荐一个方案，用主色描边标出。主按钮“扫描并预览”，下方写“扫描不会改动任何文件。”

**交互**：点击主按钮后直接进入扫描页，跳过配置页。目标文件夹使用默认值 `~/Documents/整理`。

**接口**：`app.initialize` 返回是否首次启动；`preset.list`；`profile.save`；`plan.create`。

### 6.2 首页（截图 04、05、30）

**目的**：让用户快速选方案，同时看到“上次整理可以撤销”。

```text
┌ 今天想整理哪里？ ──────────────────────────┐ ┌ 上次整理（紫色边） ┐
│ ┌ 方案 A ──────┐ ┌ 方案 B ──────┐          │ │ 1,138 个文件已移动 │
│ │图标 名称 说明 │ │              │          │ │ [撤销上次整理]     │
│ │[下载→文档 图片]│ │[图片→2026年→10月]│     │ └────────────────────┘
│ │徽章    开始设置>│ │              │        │ ┌ 继续上次方案 ──────┐
│ └──────────────┘ └──────────────┘          │ │ 下载 → 文稿/整理    │
│ ┌ 方案 C ──────┐ ┌ 方案 D ──────┐          │ │ [用这个方案重新扫描]│
│ └──────────────┘ └──────────────┘          │ └────────────────────┘
│ 最近任务（3 条，带状态和可撤销徽章）          │
└────────────────────────────────────────────┘
```

**方案卡片**包含四部分：

1. 图标块，用该方案的主要操作色。
2. 名称 + 一句话说明。
3. **结果示意条**：用文件夹标签和箭头展示“从哪里到哪里”。这是用户理解方案的核心，不能省略。
4. 安全徽章：A、B 写“只移动，不删除”（`move`）；C 写“进入隔离区，可恢复”（`quar`）；D 写“由你选择保留哪一份”（`undo`）。

整张卡片可点击，进入配置页。

**状态**：

- 没有历史：隐藏“上次整理”和“最近任务”，右栏只保留“继续上次方案”或不显示右栏。
- 上次整理已撤销或不可撤销：隐藏“上次整理”卡片。
- 启动时发现未完成的整理（截图 05）：内容区顶部显示 `warn` 色横幅，标题“上次整理没有正常结束。”，正文写明已完成数量和已修复的记录数，按钮“查看这次整理”。

**接口**：`preset.list`、`history.list(limit=3)`、`app.initialize`（返回恢复结果）。

### 6.3 方案配置页（截图 06–10）

**目的**：用最少的选择完成配置。所有检查在扫描前完成。

```text
┌ 标题：方案名                       [换一个方案] ┐
├──────────────────────────────┬─────────────────┤
│ 要整理的文件夹      [+添加文件夹] │ 整理后会是这样   │
│  下载 ~/Downloads   ✓可以读取 ×  │  整理/           │
│  包含子文件夹里的文件   [开关]   │   文档/ 图片/…    │
├──────────────────────────────┤ 这些文件会自动跳过│
│ 整理到                  [更改]  │  × 还没下载完的…  │
│  整理 ~/Documents/整理 ✓可以写入 │ 下一步只扫描……   │
├──────────────────────────────┤                 │
│ 方案参数区（每个方案不同）        │                 │
└──────────────────────────────┴─────────────────┘
底部：[返回首页]       1 个文件夹，已检查可以读取      [开始扫描]
```

**文件夹行**：图标、显示名、完整路径（Mono）、检查结果、移除按钮。来源可移除，目标不可移除，只能“更改”。

**实时检查**（在用户选择文件夹后立即调用 `profile.validate`）：

| 检查 | 失败时的行内提示 |
| --- | --- |
| 来源可读 | “没有权限读取‘团队共享’。在‘系统设置 › 隐私与安全性 › 文件与文件夹’中允许 organize 访问，或移除这个文件夹。” |
| 目标可写 | “不能写入‘整理’。请选择另一个文件夹。” |
| 来源与目标重叠 | “目标文件夹和‘下载’是同一个文件夹。请选择另一个文件夹。” |
| 目标在来源内部 | “目标文件夹在‘下载’里面。这样整理后的文件会被再次扫描。请选择‘下载’以外的文件夹。” |

有任何失败时：文件夹行变红色描边；底部摘要显示“有 N 个问题需要处理后才能扫描”；“开始扫描”禁用。

**方案参数区**：

| 方案 | 参数区内容 |
| --- | --- |
| A 按类型 | 7 个类型开关卡片（2 列），每张写出包含的扩展名。默认全部开启。全部关闭时禁用扫描。右栏树状示意同步变灰。 |
| B 按日期 | `quar` 色说明横幅：“按文件修改日期归档。修改日期不一定等于拍摄日期。”右栏示意 `图片归档/2026年/10月`。 |
| C 旧安装包 | 天数分段选择：30 / 60 / 90（默认，标“推荐”）/ 180 / 自定义。三个类型卡片：Windows 安装包、macOS 安装包（默认开启）、压缩包（默认关闭，说明“压缩包里可能有其他文件”）。目标区固定为“隔离区”，不可更改。 |
| D 重复文件 | 默认两个来源文件夹。`undo` 色横幅：“找到的重复文件不会自动处理。”可选“忽略小于 1 MB 的文件”。目标区固定为“隔离区”。 |

**右栏“整理后会是这样”**：根据参数实时变化的目录示意。它不是真实扫描结果，不显示文件数量（方案 B 的数量标注为示例，实现时去掉）。

**接口**：`profile.get`、`profile.validate`（防抖 300ms）、`profile.save`、`plan.create`。系统文件夹选择器由 Tauri 提供。

### 6.4 扫描页（截图 11、12）

**目的**：让用户看到扫描在进行，并确认扫描不会改动文件。

**布局**：内容居中。

1. **文件矩阵**：32 × 7 的小方格。一条扫描线从左到右移动，扫过的方格变为浅主色，命中的方格变为 `quar` 色。这是全产品唯一的环境动效。
2. 标题“正在扫描”（方案 D 为“正在查找重复文件”）。
3. 大号计数“3,482 个文件已检查”。
4. 当前位置，Mono 字体。
5. 方案 D 额外显示三个阶段：按大小筛选 → 比对部分内容 → 比对完整内容。当前阶段用主色描边。
6. 底部说明“扫描只读取文件信息，不会改动任何文件。”

**计划条**：一条分段横条，按数量比例显示移动、重名、隔离、跳过。下方图例给出精确数字。排除文件后，总数和大小实时减少。

**表格列**：

| 列 | 内容 |
| --- | --- |
| 勾选 | 跳过项的勾选框禁用，悬停提示“这个文件不能整理” |
| 文件 | 类型图标 + 文件名，过长时省略号，悬停显示全名 |

- 分组行的勾选框控制整组，支持“部分选中”状态。
- 表头勾选框：有任何排除项时为“部分选中”，点击恢复全选；全选时点击变为全部排除。
- 排除的行变为 45% 透明，文件名加删除线。
- 筛选和搜索可以组合。没有结果时显示“没有符合条件的文件。”
- 关闭“按规则分组”后显示平铺列表。

**计划过期**（截图 15）：收到 `PLAN_EXPIRED` 或 `PLAN_CHANGED` 时，顶部显示 `fail` 色横幅：“文件夹在预览后发生了变化。目标文件夹里新增了 3 个文件，原计划可能会重名。请重新扫描，生成新的预览。”横幅内放“重新扫描”。主按钮禁用。

**确认弹窗**（截图 16）：标题“整理 1,150 个文件？”。列出四条：移动目标、重名数量、不删除任何文件、完成后可以撤销。按钮“再看看” / “开始整理”。

**没有可整理的文件**：表格区显示“没有找到需要整理的文件。”，主按钮变为“返回修改方案”。

**性能**：表格必须虚拟滚动。一万行时滚动和勾选保持流畅。`plan.get` 按分组分页加载。

**接口**：`plan.get`、`plan.excludeItems`（勾选变化防抖 300ms 批量提交）、`run.execute`。

### 6.6 重复文件预览页（截图 17、18）

**目的**：让用户逐组决定保留哪一份。满足规格“不允许默认自动处理”。

**布局**：

- 页面工具区：“全部采用推荐”次按钮。
- 汇总面板：重复组数、文件总数、已决定 N / M、将进入隔离区数量、可以释放的空间。
- 每组一张卡片。卡片头：“第 N 组”、“3 个相同的文件，每个 612 MB”、状态徽章（“请选择保留哪一份” `warn` / “已决定” `ok`）。未决定的组卡片边框为 `warn` 色。
- 组内每个文件一行：单选按钮、文件名、“推荐保留：最早的一份”徽章（仅推荐项）、路径、修改日期、结果（待选择 / 保留 / 进入隔离区）。

**规则**：

1. 初始状态所有组都未决定。推荐项只显示徽章，不自动选中。
2. 用户点单选按钮，或点“全部采用推荐”，才算决定。
3. 还有未决定的组时，主按钮禁用，摘要写“还有 N 组没有选择保留项。”
4. 全部决定后，主按钮写“隔离 5 个重复文件”。点击后进入 L1 确认弹窗（与 6.5 同结构），再进入执行页。

**接口**：`plan.get`（重复组结构）、`plan.excludeItems`（未选中的项设为隔离）、`run.execute`。

### 6.7 执行页（截图 19、20）

**目的**：清楚表达进度，并说明“可以停止，但会先完成当前文件”。

**布局**：居中，宽 640px。

1. 标题“正在整理” + 右侧大号百分比。
2. 主进度条，下方左侧“482 / 1,150 个文件”，右侧预计剩余时间。
3. **当前文件卡片**：文件名、原位置 → 新位置。跨磁盘复制大文件时，卡片内显示单文件子进度条。
4. 三个计数卡：已完成（`ok`）、已跳过（`skip`）、失败（`fail`）。
5. 底部说明“不会覆盖任何已有文件。每一步都记录在整理历史里。”

**停止流程**：

1. 用户点“停止整理”（`fail` 描边按钮）。
2. 弹出 L1 停止确认：已整理的 N 个文件留在新位置；它们可以撤销；剩下的文件不会被处理。按钮“继续整理” / “停止整理”。
3. 确认后进入“正在停止”状态（截图 20）：
   - 标题变为“正在停止”，进度条变为 `warn` 色。
   - 当前文件卡片标签变为“正在完成当前文件”。
   - 显示 `warn` 色横幅：“正在完成当前文件，完成后停止。这个文件较大，正在跨磁盘复制。中途停止可能留下不完整的文件，所以会先完成它。”
   - 停止按钮禁用，文字“正在停止…”。
4. 当前文件完成后进入结果页，状态为“已停止”。

**执行中**：侧栏锁定。关闭窗口时弹出确认：“整理还没有完成。关闭后，当前文件完成即停止，已整理的文件可以在历史中撤销。”

**接口**：`run.execute`、事件 `run.progress`、`run.itemCompleted`、`run.completed`；`run.cancel`。

### 6.8 结果页（截图 21、22）

**目的**：突出失败处理和撤销入口。

**布局**：

1. 结果标题区：状态图标 + 一句话结论 + 用时和补充说明。
   - 全部成功：`ok` 图标，“整理完成，1,150 个文件已移动”。
   - 部分成功：`warn` 图标，“整理完成，12 个文件没有成功”，补充“失败的文件留在原位置，没有任何改动。”
   - 已停止：`warn` 图标，“已停止整理，482 个文件已完成”。
   - 全部失败：`fail` 图标，“没有文件被整理”，失败面板占满宽度。
2. 五格统计条：已移动、跳过、失败、已处理大小、进入隔离区。
3. 左栏“没有处理成功的文件”：每行左侧文件名和路径，右侧红色原因和灰色解决建议（来自第 8 节错误码表）。右上角“查看全部 12 个”。没有失败时不显示此面板。
4. 右栏“这次整理可以撤销”（`undo` 色描边卡片）：说明“撤销前会先显示预览，你可以只恢复部分文件。”按钮“撤销本次整理”。

**底部操作栏**：返回首页（次按钮）、再运行一次、查看整理记录（文字按钮）、打开目标文件夹（主按钮）。

**接口**：`run.getStatus`；“撤销本次整理”调用 `history.undoPlan` 后进入撤销预览页。

### 6.9 整理历史（截图 23）

**目的**：让用户确认每个文件的去向，并找到可撤销的整理。

**布局**：左右分栏。左栏 380px 列表，右栏详情面板。

- 页面工具区：筛选分段控件“全部 / 可撤销 / 部分成功 / 失败”。
- **列表项**：方案图标、方案名、时间和来源、状态徽章、撤销徽章、文件数。撤销记录本身也是一条历史，名称前加“撤销：”。
- **状态徽章**：完成（`ok`）、部分成功（`warn`）、已停止（`skip`）、失败（`fail`）。
- **撤销徽章**：可撤销（`undo`）、已撤销（`skip`）、无需撤销（`skip`）。
- **详情面板**：
  1. 标题区：方案名、开始时间、用时、状态徽章。
  2. 方案快照：来源、整理到、类型等参数。标注“当时的设置”，强调它来自快照而不是当前方案。
  3. 标签页：移动 N / 跳过 N / 失败 N / 隔离 N。
  4. 明细行：文件名、原位置 → 新位置（或原因）、结果徽章。
  5. 底部：“打开目标文件夹”、“撤销这次整理”（`undo` 描边）。不可撤销时隐藏撤销按钮，并写明原因。

**空状态**：“还没有整理记录。整理完成后，每个文件的去向都会记录在这里。”按钮“去首页选择方案”。

**接口**：`history.list`、`history.detail`、`history.undoPlan`。

### 6.10 撤销预览页（截图 24）

**目的**：撤销前让用户看到每个文件能否恢复、恢复到哪里。

**布局**：与预览页同结构，语义色换为 `undo`。

1. 标题“撤销预览”，说明来源整理的名称和时间。
2. 汇总面板：大号紫色数字“1,126 个文件可以恢复”；计划条四段：放回原位置、改名恢复、默认跳过、无法恢复。
3. `undo` 色横幅：“恢复不会覆盖任何文件。原位置已有同名文件时，恢复的文件会命名为‘文件名（已恢复）.扩展名’。这次撤销也会记入整理历史。”
4. 表格列：勾选、文件、恢复路径（当前位置 → 恢复位置）、结果徽章、说明。

| 情况 | 默认勾选 | 徽章 | 说明 |
| --- | --- | --- | --- |
| 原位置空闲 | 是 | 放回原位置（`undo`） | — |
| 原位置被占用 | 是 | 改名恢复（`warn`） | 原位置已有同名文件 |

**完成后**：回到整理历史，显示提示“已恢复 1,126 个文件。这次撤销也记入了整理历史。”撤销过程超过 2 秒时，显示与执行页相同结构的进度页，标题“正在恢复”。

**接口**：`history.undoPlan`（返回预览）、`history.undo`（传入勾选项）、事件 `undo.progress`、`undo.completed`。

## 8. 错误码文案

后端返回错误码和参数，前端按下表生成中文。每条都是“发生了什么 + 怎么做”。

## 10. 可访问性与性能

1. 全部操作可用键盘完成。焦点环为 2px `primary`，偏移 2px。
2. 表格支持方向键移动行、空格切换勾选。
3. 颜色不是唯一信息来源。每个语义色都配有文字徽章。
4. 正文与背景对比度至少 4.5:1。`text-3` 只用于辅助信息。
5. 开启系统“减少动态效果”时，扫描矩阵改为静态进度条。
6. 预览、撤销预览、隔离区表格使用虚拟滚动。一万行时保持 60fps 滚动。
7. 进度事件在前端节流到每 100ms 更新一次界面。

## 11. 实现验收清单

- [ ] 任务流每页只有一个主按钮，位置固定在底部操作栏右侧。
- [ ] 主按钮文字包含动作和数量，例如“整理 1,150 个文件”。
- [ ] 界面上没有出现“删除”（“永久删除：从不”除外）、YAML、哈希等词。
- [ ] 预览页排除文件后，总数、大小、主按钮数量同时更新。
- [ ] 计划过期时，主按钮禁用，并显示“重新扫描”。
- [ ] 重复文件预览初始不选中任何保留项；全部决定前主按钮禁用。
- [ ] 执行中侧栏锁定；停止后显示“正在完成当前文件”状态。
- [ ] 结果页有失败时，失败面板在撤销卡片之前（左侧）。
- [ ] 撤销一定先进入撤销预览页。
- [ ] 移入系统回收站使用 L2 弹窗，默认焦点在“取消”。
- [ ] 每个错误码都按第 8 节显示标题和建议。
- [ ] 深色、浅色两套主题都通过对比度检查。
- [ ] 一万行预览数据下，滚动、勾选、搜索不卡顿。

## 12. 开放问题

1. **默认主题**：设置默认“跟随系统”。设计稿以深色为基准。是否需要首次启动强制深色以突出科技感？建议不强制。
2. **撤销预览中被修改过的文件能否手动勾选**：本稿允许，需产品确认。
3. **“恢复到其他位置”接口参数**：需要后端在 `quarantine.restore` 中支持目标文件夹。
4. **引导页推荐方案规则**：下载 → A、图片 → B、桌面 → A。需产品确认。
5. **方案 C 的天数“自定义”**：建议用数字输入，范围 7–3650 天。

已定决策：Run 的 cancelled 状态在界面上统一写“已停止”，与“停止整理”按钮一致。
